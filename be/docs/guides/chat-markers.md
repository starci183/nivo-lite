# Chat delivery, seen, mute and typing

The chat-state API uses the same authenticated principal and selected workspace as the existing Office and agent-chat APIs. A target has `room` and `conversationId`: omit both for the general Office thread, set `room` for a department, or set `conversationId` for an agent test or customer conversation. Supplying both is refused. The caller must be an active member and the target must belong to that workspace.

`chatMarkerState(input: ChatTargetInput!)` returns the caller's `muted` preference and `lastOwnMessage`. The latter is null until the caller has posted an attributed message in that target. It identifies the caller's latest message even when another member has posted a newer line. Historical messages are not attributed by matching display names.

The persisted states are `sent`, `delivered`, and `seen`. Pending sending is local UI state. `markChatDelivered(input: ChatReceiptInput!)` acknowledges the last persisted `messageId` actually fetched by the client, including while the thread is hidden or unfocused; it must not be called merely because a notification arrived. The web client keeps its selected thread's fetch poll running in hidden tabs. `markChatRead` takes the same input only while that thread is displayed in a visible, focused document. Returning to the thread acknowledges its fetched cursor without advancing past it. Cursors advance monotonically and acknowledge no later message. A caller's own receipts never upgrade their own message's status. Only receipts from other active workspace members count; these are client receipts, not external Zalo, Telegram, or customer-provider delivery acknowledgements.

For Office rooms, seen state reuses the exact target's `office_rooms_reads` marker, matching its unread count. The general Office thread displays all workspace messages but has its own aggregate marker: reading it clears only Office unread and changes only Office receipts. Each department has a separate marker, unread count and receipt state; reading a department does not mark Office or another department read. Delivery cursors use the same independent target scopes and never clear unread counts. Conversation receipts use `chat_markers`; they do not compute unread counts. Existing unread APIs retain their own responsibilities.

`lastOwnMessage.seenBy` holds at most three readers in deterministic order, each with `id`, `name`, and `avatarSeed`. `seenByCount` is the full reader count, so the UI can show `+N` for the remainder. An avatar seed is a stable account ID, not a stored provider image URL.

`setChatMuted(input: ChatMuteInput!)` stores the caller's boolean `muted` preference for the target. The frontend reads `chatMarkerState.muted` to choose a dot instead of an unread count. Muting does not acknowledge a message.

Typing is an ephemeral server-sent-event push on the app's own realtime door `GET /realtime/chat-typing` (query `room` or `conversationId`, none for the general Office). The frontend streams it with its bearer token and sends transitions through the `setChatTyping` mutation; it never publishes to the stream. The mutation proves membership of the target and pushes one `{ id, actorId, actorName, state: start|stop, at }` frame to the stream of every other admitted member, so a non-member's stream stays silent. A start frame lapses five seconds after its time even if no stop arrives; a stop clears it at once. Refresh every three seconds while composing and send stop on send, blur, or cancellation. The stream keeps a bounded replay for `Last-Event-ID` only.
